# 多 Agent 协作工作流改进设计

> 状态：已评审，待实施
> 日期：2026-08-03
> 涉及文件：`docs/ai-workflow/PLAN.md`、`AGENTS.md`

## 背景

当前工作流（Claude 计划 → Codex 执行 → Claude review）已通过 WhackAMole 任务验证可行，但存在三个改进点：

1. PLAN.md 模板没有持久化，每次新任务依赖 Claude 记忆恢复模板结构
2. 所有任务共用一套细粒度模板，对大任务不友好
3. Review 结果只有"阻塞/非阻塞"两档，导致本可顺手修的微优化堆积进 backlog

## 改进 1：PLAN.md 顶部折叠模板骨架

### 目标

模板永远保留在文件顶部，新任务只覆盖动态正文区，不依赖 Claude 记忆恢复结构。

### 方案

在 PLAN.md 顶部用 HTML 注释包裹模板骨架。VS Code 默认折叠 HTML 注释块，零视觉负担。正文区用 `TASK_BODY` 标记明确边界。

### 结构

```
<!-- TEMPLATE:START -->
  [模板说明 + 完整模板骨架]
<!-- TEMPLATE:END -->
---
[ TASK_BODY：动态任务区，每次新任务覆盖此区域 ]
```

### 覆盖规则

- Claude 新建任务：复制 TEMPLATE 区结构 → 填入 TASK_BODY 区
- Codex 执行：只修改 TASK_BODY 区的勾选和交接记录
- Claude review：只修改 TASK_BODY 区的 review checklist 和修复方案
- 任务提交后：清空 TASK_BODY 区（回到空骨架），TEMPLATE 区永远不动

## 改进 2：粗细双模式 PLAN

### 目标

让 Claude 根据任务规模选择粒度，避免大任务被行号级指令拖累。

### 模式定义

| 维度 | 细模式（micro） | 粗模式（macro） |
|------|----------------|-----------------|
| 适用场景 | ≤ 50 行改动、bug 修复、单文件修改 | 新游戏、多文件重构、架构级变更 |
| 文件级修改点 | 表格：文件 + 具体改动 + 完成勾选 | 文字描述：改哪些模块、不改哪些 |
| 实现细节 | 精确到行号 + 改前/改后代码片段 | 只给约束（"必须复用 X"、"禁止新建 Y"） |
| Review Checklist | 偏正确性：逻辑、空安全、build | 偏架构合规：分层、复用、命名 |
| Codex 自由度 | 按指令执行，不改逻辑 | 自主决定实现细节，Claude 只验收结果 |

### 选择逻辑

Claude 创建计划时，在 TASK_BODY 顶部声明模式：

```markdown
# 任务模式：细（micro）
  — 或 —
# 任务模式：粗（macro）
```

模板中两种模式共享：任务目标、验收标准、Review Checklist、参考实现、交接记录、修复方案。差异仅在"文件级修改点"和"实现细节"的粒度。

## 改进 3：Review 四级分级标准

### 目标

把 review 结果从二档（阻塞/非阻塞）细化到四档，让 Codex 明确知道哪些必须修、哪些顺手修、哪些进 backlog。

### 分级定义

| 级别 | 标识 | 含义 | 处理方式 | 典型示例 |
|------|------|------|---------|---------|
| P0 正确性 | 🔴 | 逻辑/渲染/数据错误 | 阻塞，Codex 必须修 | 飘字坐标偏移、得分计算错误、空指针 |
| P1 规范 | 🟡 | 违反 AGENTS.md 硬规则 | 阻塞，Codex 必须修 | 新建了本应复用的 composable、未用 GameLayout |
| P2 打磨 | 🔵 | 风格/微优化、零风险 | 不进 backlog，Codex 顺手修 | 单双引号、冗余媒体查询、未使用变量 |
| P3 可选 | ⚪ | 后续可做的改进 | 进 backlog | 动画曲线优化、新增触觉反馈 |

### Review 结果写法

```markdown
## Review 结果

### 阻塞项（P0 / P1）— 必须修复
- [ ] 🔴 P0: <问题描述>
- [ ] 🟡 P1: <问题描述>

### 非阻塞项
- [ ] 🔵 P2: <问题描述>（顺手修）
- [ ] ⚪ P3: <问题描述>（backlog）
```

### 终止条件（更新）

> P0 + P1 清零 + P2 已修或明确跳过 + P3 进 backlog → 可提交。
> 最多 2 轮 review；第 3 轮仍存在 P0/P1 → 人工介入。

**与旧规则的兼容性**：原来的"阻塞"= P0+P1，"非阻塞"= P2+P3。分级是细化，不是推翻。
